# 路线设计与决策手册

## 架构不变量

```
家里 Windows / 原 v2rayN ──────────────── BWG Xray/sing-box（原样）
家里原 CPA 客户端 ────────────────────── BWG Nginx TLS → Admission → CPA Core
单位 Windows / 原 v2rayN + 独立试验配置 ─ 获准路线 ─ BWG 现有网络服务/CPA
单位国内 GLM + 内网 ──────────────────── 原有线网络（保留）
阿里云 ECS ──────────────────────────── QQ 运维优化；可选获准固定应用
```

不默认引入第二套代理客户端/CPA/SSH 控制面。WEB 与 CPA 可分路径；只有真实端到端测试决定。单位政府网是最终测试环境，不能通过移动热点替代。外部网络接入授权及承载方许可为硬门槛，不可用高性能、低价格抵消。

## 候选与最低试验

| 路线 | 前置条件 | T1 / 试验 | 决策 |
|---|---|---|---|
| D 现有 v2rayN/BWG | 既有接入用途被允许 | 原获准节点、目标真实可达，记录实际网络源接口 | 满足则零新增，保留原配置 |
| E 单位正式接入 | IT 提供批准的方案/白名单 | 按 IT 指定端点/方式测试 WEB/GIT/API | 若满足优先，减少故障点 |
| H 家庭接入 | 单位允许家庭远程接入；家里上行/可达/权限 | 先测本 HOME 和外置 ONOFFICE 专用常驻机上的真实获准服务，再验证业务；保持原家庭 v2rayN | HOME 仅用于隔离试验；需长期运行先测 ONOFFICE，仍不足才考虑 N150 |
| C 阿里云应用 | 厂商与单位确认具体固定应用业务许可 | 单位→ECS 的业务端点；ECS→BWG 已有受保护 HTTPS | 仅应用，不通用跨境中转；3Mbps 与 QQ 共享 |
| M 组合 | 每条路径均获准 | 分别测网页/Git、API | 两项目标均达成且复杂度可接受 |

### 家庭候选的具体实施边界
- HOME 通过华硕后台只读核对 WAN IPv4、IPv6、DDNS、DHCP；核对公网地址时确保不是经代理得到的 VPS 出口。WAN 私网或 CGNAT 只能提示入站可能受限；两端 IPv6 及 UDP 可达须实测。记录家庭上行和晚高峰。先测 HOME 与 ONOFFICE，不默认买硬件。
- 若单位明确允许，评估 WireGuard（公网条件、路由器单一 UDP 映射、严格对端 ACL）或 Tailscale（最小 grants、direct/relay、与现有 VPN/代理兼容）。只访问获准的家庭服务，不发布整个家庭 LAN，不默认设置 exit node，不扩大默认路由。实际 VPN 版本与 Windows 支持能力先核对，采用独立 peer 身份和可撤销权限。不得暴露公网 RDP 或管理口。
- 远程浏览器/桌面仅在明确允许的用途内试验；如果影响家庭当前交互会话，停止并考虑 ONOFFICE 专用机的独立会话。它只证明远程浏览能力，不能代替单位本机浏览/Git/Codex 测试。若需要本机应用访问，使用单位明确批准的客户端接入和范围，优先复用已安装 v2rayN 的受支持配置；不能仅假定某版本支持链式路由或 SOCKS/HTTP 接入。实际配置由 HOME/OFFICE 基于运行版本和获准接口生成 diff，不发明未验证命令。
- ONOFFICE 是用户为 H 提供的独立常驻 Windows 主机，与日常 HOME 分开；其主机名、现有角色、仓库、代理与使用边界尚未现场核验，不能据此推断已运行或有 24h 能力。先采集身份、网络、休眠、更新、远程会话与恢复条件，并把 H 试验的专用会话与日常家庭交互会话隔离。
- H 只提供获准的家庭服务访问、链路和可恢复性证据；远程浏览器列 REMOTE-WEB，不能替代 WIRED-WEB 或 WIRED-GIT。HOME 可作隔离试验；外置 ONOFFICE 先实测，仍不足才评估 N150 8–16GB/256–512GB、有线、Debian、来电自启、服务自动恢复。购买不是施工前置。所有候选的休眠/更新/远程会话锁屏必须实测，不能宣布 24h 已通过。

### 阿里云候选的具体边界
阿里云普通 ECS 使用须知禁止流量穿透（见 06）。不为通用境外网页流量搭建中转，不将移除 QQ 当作解除限制。C 的适用状态默认是 BLOCKED，直到实际用途获准且交付边界成立。现有公开 Caddy 80/443 已有 ICP 边缘拦截记录；不能把修改 Caddy、容器网络或 Host 当作绕过合规或用途限制。优先单位正式接入直接访问 BWG 已有 HTTPS，避免重复入口。若确需复用现有 Caddy，须由 HOME 审查实际部署和证书域名、网络、安全组、精确业务路径/方法与固定上游、认证、SSE、日志和取消行为；无动态上游/CONNECT/管理路径。客户端与上游均 TLS 验证，不泄露真实 capability path，不绕过 Nginx 或 Admission。详细执行规则见 03；未获批准不部署。

### 决策证据表（每条路线填写）
授权状态/依据编号；测试环境（有线独立/热点/双网已证实）；两段链路和端到端；WEB/GIT/CPA 分项状态；延迟/TTFT/完成率（小样本标明）；带宽实测与峰值；现有服务影响；增量年费/一次性；维护复杂度/故障域；下一动作/负责人。授权不明→BLOCKED；基础探测失败不直接证明所有协议不可达；无法实际业务→NOT_RUN。优先可达且获准、成本低、故障域少、无需改变原配置的路线。
