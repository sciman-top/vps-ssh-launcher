# OFFICE 双网络试验与 T1/T2/T3 人工门禁

## 1. 网络环境分级

有线政府网可使用国内 GLM（用户确认）；手机热点是 Git/依赖/对照辅助。单位允许时可并存，不桥接、不共享、不启用跨网 IP 转发。不得擅自改默认路由、接口 metric、DNS、TUN、系统代理或安全软件。双网络下 Windows 依目的前缀、接口/路由 metric、IPv4/IPv6、应用代理决定真实出口；浏览器连 loopback 不能证明 v2rayN 核心出网路径。原配置是回退，不覆盖。

四种标签：HOTSPOT_BASELINE / WIRED_BASELINE / DUAL_PROVEN（实际出口证实）/ WIRED_ONLY。无法证明实际出口→UNVERIFIED，不计通过。双网下如确需隔离测试路由，另交 IT 与用户批准的精确目标、变更和恢复；不能以调整默认路由代替证据。

## 2. 各门禁操作步骤

T1：完成 A0/B0、候选端点有明确许可和真实监听后、批量生产配置前。测试已获准的家庭/现有 BWG/单位正式入口或固定应用；记录 DNS、TCP、TLS/UDP 对应协议的真实握手，区分监听未就绪、鉴权、路由、端口不可达。T1 允许审批最小 pilot，不能要求先全部部署。T1 不测所有应用，输出 T1-RESULT。

T2：HOME 发布 SERVER-READY，OFFICE 已配置并初步验证后。断热点实际打开网站、Git、调用 CPA、实际 Codex；失败保持有线诊断，GLM 可继续。输出 CLIENT-RESULT。

T3：修复后，正式有线独立终验；检查完整业务、原有环境、已批准的断线恢复、现有 HOME/BWG/QQ 状态。记录样本范围，不把短测当长期 SLA。输出 FINAL-ACCEPTANCE。

**每个节点均必须主动发出人工提示，不自动关闭网卡，不要求用户先手动反复试错：**

> 已到 T{1/2/3}，本阶段准备和审批已完成。请保存当前工作，保持单位有线网线连接，手动断开手机热点 Wi-Fi。确认断开后回复“已断开热点”。国内 GLM 在有线网络可用，我将先验证 GLM，然后继续执行本阶段测试。已保存本地状态和日志目录：<实际路径>。若出现异常，可重新连接热点，之后从保存状态续作。请不要改变其他网络设置。

断开前：保存已实施配置/阶段/审批记录；本地测试工具、依赖、日志目录就绪；记录需要用户操作的网页登录/打印等项目；确认可恢复热点与原配置。断开后：用户确认；采集有线接口、Wi-Fi断开、默认路由和其他 VPN/IPv6 出口；GLM 实际完成一条小请求确认国内路径；继续执行。若 GLM 意外中断，使用本地脚本记录结果，恢复热点后续作。通常失败不必恢复热点，除非需同步 Git/依赖或恢复异常连接。

## 3. 只读证据及脚本

优先现有仓库的客户端诊断工具。补充 PowerShell 脚本 `office-net-audit.ps1` 可运行于 Windows PowerShell 5.1 或 pwsh；不改网络、不读 API key、只做指定获准 TCP 端点及接口/路由证据。输出含本机地址和目标地址，仅本地私有保存，人工脱敏后交接。示例（用真实批准的主机名/端口替换）:

```powershell
.\scripts\office-net-audit.ps1 -Phase T1 -NetworkMode WIRED_ONLY -ApprovedHost '<获准的实际主机名>' -ApprovedPort 443 -EvidenceDirectory 'D:\Private\HG03-evidence' -ApplicationProcessId 0
```

`NetworkMode` 是测试人员声明，不是脚本认证。WIRED_ONLY 下检测到任一处于 Up 状态的 VPN/TUN/WireGuard/Tailscale 适配器（即使未接管默认路由）也输出 UNVERIFIED，须人工核实或断开后重测。v4.1 输出 `EVIDENCE_STATUS=UNVERIFIED` 时，即使 TCP 成功也不得记 T1 PASS。脚本的 TCP 探测不代表 v2rayN/浏览器/CPA 路径成功，不能用于判 UDP 失败；v2rayN 使用本地代理时，查实际核心连接的远端地址与本地源 IP，结合 `Find-NetRoute`、`Get-NetTCPConnection`（UDP 需相应获准日志/握手证据）和服务端时间戳。注意 DNS 与实际连接的 IPv4/IPv6 可能不同；查询的最佳路由也不等于应用实际走的路径。只有应用真实业务测试才计通过。

## 4. T2/T3 业务验收矩阵

| 项目 | 实际通过条件 |
|---|---|
| WEB | 单位本机浏览器通过获准路径实际加载用户所需站点、静态资源与必要登录/小文件下载；记录实际页面功能。远程桌面访问单列 REMOTE-WEB，除非用户明确接受替代，不算本机通过 |
| GIT | 同一真实获准远端，先 `git ls-remote`（本地配置不写，仍涉及远端认证）；再获准执行 fetch，验证认证、对象下载/目标 commit。必要 push 用批准的独立测试分支，不污染正式分支。保护 dirty tree，不能用热点或本地缓存冒充成功 |
| CPA | 实际受保护 HTTPS URL，证书校验、已授权 key；模型列表与实际支持的模型/协议；真实 Responses 和 Chat Completions（对不支持的模型标 N/A/解释），错误鉴权应拒绝；无管理口/内部端口暴露 |
| SSE | 按真实协议收到完整事件序列及成功终态（例如 Responses 的 response.completed 且状态成功；Chat Completions 的协议规定终止标记并无错误）；HTTP 200、部分 delta、EOF、握手不算成功。记录 TTFT、总耗时、终止状态、错误分类，不保存正文 |
| CODEX | 现有客户端支持的独立 provider，完成一个无单位敏感数据的实际小任务并验证结果；真实长任务仅按批准配额少量测试，记录持续时间、完成/中断 |
| GLM | 原有国内 provider 继续完成实际小请求，不经新增路径强制转发 |
| INTRANET | 原教务系统、打印机、内网、安全软件在用户/IT允许的测试下回归 |
| HOME/BWG | 家里原 v2rayN、CPA 正常，原 Guardrails 三层、lane、Xray/sing-box 和维护任务无意外变更 |
| ECS/QQ | 独立优化报告、实测资源前后对比、机器人回归或已批准停用/迁移/卸载状态 |

测试策略：默认每个 CPA 模型/协议单发、零自动重试，按批准配额在指定窗口验收；网页实际业务按必要次数检查，不制造载荷。稳定性只记录实际自然流量窗口；未进行则 `NOT_RUN`。断线恢复只验证新连接，不重放已计费 POST，不承诺已有 SSE 自动续传。记录四层 429 归因（本机、Nginx、Admission、上游）和实际证据。所有登录、令牌、URL capability 和生产内容只在本机安全配置，报告不输出；请求 ID 仍要由服务端新鲜记录证明。

T3 结果必须为 WIRED_ONLY，用户确认热点已断、实际路径证据齐全。P0 全通过才能说主要目标完成；GIT 若未通，完整交付仍未完成。`git ls-remote` 只证明远端引用可见，不能代替实际 fetch/对象下载；热点成功不算有线成功。FAIL/BLOCKED/NOT_RUN/UNVERIFIED 均非 PASS。最终验收附 schema 校验回执；CPA/SSE/CODEX 记 PASS 必须携带 `request_consistency` 且 `server_seen=true`（对照服务端新鲜记录）；无法完成对账时该项只能记 UNVERIFIED，不得记 PASS。schema 校验本身不是业务验收。
