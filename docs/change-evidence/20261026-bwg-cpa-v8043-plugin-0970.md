`main.go` config-list hunk: upstream inserted the `account_max_concurrent`
entry after `stream_head_timeout`, breaking that hunk's context
(scheduler/usage_config/active_auth/test hunks still matched). Per the
patches' own fail-closed contract this was resolved by explicit review, not
force: new `scripts/patches/workbuddy-v0.8.84-{selected-account,account-failover}.patch`
were generated by staged application with identical semantics — the only
code delta is the same one-line `scheduler_mode` enum/description
replacement, now with the upstream context line included. The account-failover
patch needed offsets only. Both were verified to apply in sequence to a
pristine v0.8.84 extract and to reproduce the staged trees bit-for-bit before
the remote build ran.
