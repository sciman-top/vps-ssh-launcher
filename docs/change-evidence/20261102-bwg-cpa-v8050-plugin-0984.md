## 实际修复

审查发现 `isChannelRiskControl` 用整数结构的 `Code` 接上游
`{"code":"11-128"}`，JSON 解码失败后仅依赖文本容错；该路径不能形成
新构建要求的渠道冷却分类。修复将既有业务码保持整数，另用仅含字符串
`code` 的结构解析 11-128；4xx 的 11-128 进入本地 `channel_rejected`
冷却并形成硬停，普通 429/容量冷却继续交还宿主。两项账号/渠道硬停测试、
一项普通容量 defer 测试及 auth.parse 测试均通过，全套
`go test -count=1 ./...` 通过。
