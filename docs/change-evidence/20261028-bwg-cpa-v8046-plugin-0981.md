## Patch lineage fix (project code)

The first on-box build failed at
`workbuddy-v0.8.87-selected-account.patch` / `usage_config.go:207`. Root
cause: that patch file ended in a single CRLF file terminator; the driver's
CRLF→LF transport normalization turned it into a phantom empty context
line, `git apply --recount` counted it into the hunk, and the reformatted
0.9.81 sources no longer matched (the CRLF original passed because the
stray `\r` line was skipped as "unexpected"). Both local patches were
regenerated from pristine v0.8.89 plus the effective edits
(`git diff --cached` after applying the originals, new test files included)
as canonical LF patches with correct hunk counts:

- `scripts/patches/workbuddy-v0.8.89-selected-account.patch` (5 files,
  semantics identical to the 0.8.87 lineage)
- `scripts/patches/workbuddy-v0.8.89-account-failover.patch` (5 files,
  semantics identical to the 0.8.84 lineage)

The 0.8.68–0.8.87 files stay as frozen lineage; the v0.8.89 pair is the
active one. A first regeneration pass accidentally embedded the sibling
patch artifact as a new-file diff (`git add -A` before writing the patch
out of the tree); caught by the fresh-tree verify loop and redone with the
patch outputs outside the worktree.
