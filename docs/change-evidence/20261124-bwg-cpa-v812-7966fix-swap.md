## 修复设计（三提交，merge 树 `55594068` 之上）

1. **emit-once 工具调用发射**（`internal/translator/antigravity/openai/chat-completions/antigravity_openai_response.go`）：
   4df055de 的"start 开括号+碎片 delta+终末闭合"形状与 6825 族客户端契约
   （每调用单 delta 完整参数、索引严格递增）互斥。改为**缓冲-组装-单发射**：
   start 缓冲 ArgMembers；无 `willContinue`/partialArgs 标记的 start 携带
   完整参数 → 立即单 delta 发射（并行完整调用=真实生产形状）；标记的流式
   start 缓冲至 text/terminal flush 时组装为完整 JSON 单 delta；已发射调用的
   未标记续块降级为 index-addressed 片段（best-effort，保留 4df055de 修的
   #7912 续块不丢失语义）。
2. **seen 条件延后**（`internal/translator/antigravity/gemini/antigravity_gemini_request.go`）：
   ae88b00c 的无条件延后把中断场景的纯用户消息排到了响应组之后（空 text
   part 错位）。加 `groupResponsesSeen`（组开=false，见响应=true）：
   **未见过组内响应的用户内容按时间序直接落位**（中断测试期望），见过才延后
   （ae88b00c 自身两测试的分组语义保持）。三方测试全兼容。
3. **issue6332 测试适配**：crossauth 叠层的 `auth:<hash8>:` sessionKey 前缀
   使上游测试的未加前缀直读落空（生产读写同键无影响；v8.1.1 生产代树同样
   FAIL=既有基线错配，非新回归）。测试读键改为同构 scoped key，测试意图
   （replay 跟随上游完整性而非投递）不变。

**测试契约裁决记录**：6825 族（真实客户端形状）与 4df055de 自带测试（流式
碎片形状）冲突时以客户端契约为准；后者的流式意图由 `willContinue` 缓冲路径
保留，其两个单测重写至 emit-once 契约（缓冲不提前发射/flush 单 delta 完整
参数/finish_reason=tool_calls 不变）。
